CampusHelp – Prototype Test Cases
Testing Overview
The purpose of this document is to verify the main functions of the CampusHelp student service request portal. Testing is based on the proposed prototype and documented screen flow. Some functions are simulated and are not part of a fully developed application.
Test Case 1 – Required Fields
Test ID: TC01
Steps: Open the student request form, leave required fields empty, and click Submit.
Expected Result: The system displays validation messages and does not accept an incomplete request.
Actual Result: Validation behavior is demonstrated in the prototype.
Status: Pass (simulated)
Test Case 2 – Request Category Selection
Test ID: TC02
Steps: Open the request form and select a category such as IT Support, Library Assistance, or Classroom Maintenance.
Expected Result: The selected category is displayed correctly.
Actual Result: Category selection is shown in the prototype.
Status: Pass (simulated)
Test Case 3 – Request Priority Selection
Test ID: TC03
Steps: Select a priority level: Low, Medium, or High.
Expected Result: The selected priority is displayed with the submitted request.
Actual Result: Priority selection is represented in the prototype.
Status: Pass (simulated)
Test Case 4 – Submission Confirmation
Test ID: TC04
Steps: Complete the request form and click Submit.
Expected Result: A confirmation message appears after submission.
Actual Result: The confirmation screen is demonstrated in the proposed flow.
Status: Pass (simulated)
Test Case 5 – Request Status Visibility
Test ID: TC05
Steps: Open the student request tracking screen and check the request status.
Expected Result: The student can see whether the request is Open, In Progress, or Completed.
Actual Result: Status visibility is included in the proposed screen flow.
Status: Pass (simulated)
Test Case 6 – Administrator Dashboard
Test ID: TC06
Steps: Open the administrator dashboard and review the displayed requests.
Expected Result: The administrator can view requests and their statuses.
Actual Result: Dashboard information is represented in the prototype.
Status: Pass (simulated)
Testing Conclusion
The six test cases cover the main requirements of the CampusHelp portal. The results are based on the proposed prototype and documented screen flow. The functionality is simulated and does not represent a fully implemented production system
