# WORK BREAKDOWN STRUCTURE (WBS)
## CampusHelp – University Student Service Request Portal

### 1.0 CampusHelp Project

The CampusHelp project is divided into four major phases: Initiation, Planning, Execution, and Closure.

### 1.1 Initiation

**1.1.1 Project Charter**
- Define the project purpose and objectives.
- Identify the project sponsor and project manager.
- Establish the initial project scope and constraints.

**1.1.2 Requirements**
- Identify student service requirements.
- Gather stakeholder expectations.
- Define the main system features.

**1.1.3 WBS**
- Divide the project into manageable work packages.
- Identify major activities and deliverables.
- Assign responsibilities to team members.

### 1.2 Planning

**1.2.1 Schedule**
- Prepare the project timeline.
- Define task dependencies.
- Establish milestone deadlines.

**1.2.2 Wireframes**
- Design the student request submission screen.
- Design the administrator dashboard.
- Prepare initial interface mockups.

**1.2.3 Risk & Quality Plan**
- Identify potential project risks.
- Prepare a risk register.
- Define quality standards and test procedures.

### 1.3 Execution

**1.3.1 Student Interface**
- Create the student request submission prototype.
- Include request categories and priority levels.
- Demonstrate request tracking.

**1.3.2 Admin Interface**
- Create the administrator dashboard prototype.
- Demonstrate request assignment.
- Display open, ongoing, and completed requests.

**1.3.3 Testing**
- Prepare test cases.
- Test the prototype and interface flow.
- Record test results and defects.

### 1.4 Closure

**1.4.1 Change Control**
- Evaluate the proposed change request.
- Analyze its impact on scope, cost, and schedule.
- Document the final decision.

**1.4.2 Final Verification**
- Review completed project deliverables.
- Verify test results.
- Check GitHub Issues and Pull Requests.

**1.4.3 Project Closure**
- Prepare the final project report.
- Document lessons learned.
- Submit all project materials.

---

### 2. WBS Summary

| Phase | Main Deliverables |
|---|---|
| Initiation | Charter, Requirements, WBS |
| Planning | Schedule, Wireframes, Risk & Quality Plan |
| Execution | Student Interface, Admin Interface, Testing |
| Closure | Change Control, Final Verification, Project Closure |

### 3. Project Completion

All work packages will be monitored through GitHub Issues and the Project Board. Each deliverable will be reviewed before the project is officially closed.
