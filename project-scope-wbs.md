CampusHelp – Project Scope and Work Breakdown Structure (WBS)
1. Project Overview
CampusHelp is a proposed web-based University Student Service Request Portal. The project aims to help students submit service requests and monitor their progress through a centralized system.
The university currently receives requests through emails and paper forms, making request tracking difficult.
2. Project Objectives
The main objectives are:
Provide students with a way to submit service requests.
Organize requests by category and priority.
Allow students to track their requests using a unique request ID.
Enable administrators to assign requests.
Support request status updates.
Provide an administrator dashboard showing open, ongoing, and completed requests.
3. Project Scope
In Scope
The project includes:
Student request submission interface.
Request categories and priority levels.
Request tracking and status visibility.
Administrator request assignment.
Request status management.
Administrator dashboard prototype.
Interface mockups and project demonstration.
Project documentation and testing.
Out of Scope
The project does not include:
A fully developed production-ready application.
Complete database implementation.
Real email notification integration.
Deployment of a live university system.
Integration with external university platforms.
4. Project Deliverables
Project Charter.
Stakeholder Requirements Document.
Project Scope and WBS.
Project Schedule and Budget.
Initial Wireframes.
Risk Register and Quality Plan.
Student Request Interface Prototype.
Administrator Dashboard Prototype.
Test Cases and Testing Results.
Change Request Document.
Final Verification Report.
Consolidated Final Project Report.
5. Work Breakdown Structure (WBS)
1. Project Initiation
1.1 Develop Project Charter.
1.2 Identify Stakeholder Requirements.
1.3 Define Project Scope.
1.4 Develop Initial WBS.
2. Project Planning
2.1 Develop Project Schedule.
2.2 Estimate Project Budget and Resources.
2.3 Design Initial Wireframes.
2.4 Develop Risk Register.
2.5 Prepare Quality Plan.
3. Project Execution
3.1 Develop Student Request Interface.
3.2 Develop Administrator Dashboard.
3.3 Prepare Prototype Demonstration.
3.4 Develop Test Cases.
3.5 Execute Prototype Testing.
4. Monitoring and Closure
4.1 Monitor Project Progress.
4.2 Evaluate Change Requests.
4.3 Conduct Final Project Verification.
4.4 Review Project Issues and Deliverables.
4.5 Prepare Final Project Report.
4.6 Submit Final Project.
6. Project Constraints
The project must be completed within 10 working days.
The team consists of exactly three students.
All project activities must be documented through GitHub.
The project focuses on planning, documentation, mockups, and prototype demonstration rather than full software development.
The team must complete the required deliverables within the assigned schedule.
7. Project Assumptions
University students and administrators are the main stakeholders.
Team members have access to the GitHub repository.
The team can prepare interface mockups using available design tools.
Testing can be conducted using a prototype or documented screen flow.
The university administration is treated as the simulated project sponsor.
8. Conclusion
The project scope defines the main activities and boundaries of the CampusHelp project. The WBS divides the project into four major phases: initiation, planning, execution, and monitoring and closure.
This structure helps the team organize responsibilities, identify deliverables, and monitor project progress throughout the 10-working-day schedule.
